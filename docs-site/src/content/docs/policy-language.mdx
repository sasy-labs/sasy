A SASY policy answers a question about a proposed action: may this authenticated
caller perform it, given the recorded context? Policies use Soufflé Datalog in
`.dl` files. The engine supplies the common types and relations; your file adds
rules.

## A small policy

Save this as `read-only.dl`:

```prolog
// Allow Read calls. Other tool names have no allowlist match.
IsAuthorized(idx) :-
    Actions(idx, action),
    IsTool(action, "Read").

// @deny_message: Writes are disabled in this session
// @suggestion: Read the existing file and describe the proposed change
Unauthorized(idx) :-
    Actions(idx, action),
    IsTool(action, "Write").
```

The first rule allows a `Read` call. The second explicitly blocks `Write` and
provides feedback. An action with no allowlist match is not authorized; a hard
denial wins even if an allow rule also matches.

Bind the file to a session with `sasy.session(policy=Path("read-only.dl"))`, as in
[use the SDK directly](/quickstart/). The engine compiles it when the session
binds. The application checks the actual proposed action before executing it.
This policy checks tool names; it does not restrict which files `Read` may access.

## Facts and rules

A **relation** is a table of facts. `Actions` contains the proposed actions,
`Principal` identifies the authenticated caller, and `Edge` records message
dependencies. The engine supplies those facts; your rules derive new ones.

Read `IsAuthorized(idx) :- Actions(idx, action), IsTool(action, "Read").` as:
“put `idx` on the allowlist if that action is a Read tool call.”

- Commas mean AND. Separate rules with the same head mean OR.
- Variables join matching values across relations. `_` matches any value without
  retaining a binding; quoted strings are constants.
- Rules end with a period. `//` starts a comment.
- Declare a relation you introduce with `.decl`; common relations are already
  declared by the engine.

A check can propose several actions. `idx` is their zero-based index, shared by
allow and denial results. A tool action is a tagged value, such as this input fact:

```prolog
Actions(0, $CallTool("Read", "{\"file_path\":\"notes.txt\"}")).
```

The application supplies this fact; do not hard-code it in a policy.
`$CallTool` contains the tool name and a JSON argument string.

## Read an argument

An allow rule can constrain the action's arguments:

```prolog
IsAuthorized(idx) :-
    Actions(idx, action),
    action = $CallTool("publish", args),
    @json_get_str(args, "destination") = "internal".
```

`@json_get_str` reads a string field. A missing field does not match `"internal"`,
so this rule alone does not allow a publication with no destination. More rules
can inspect recorded messages, successful tool results, and authenticated roles.
